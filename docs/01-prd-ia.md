# 01. 기획서 · 정보구조 (PRD / IA)

> 최종 수정: 2026-09-02

---

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | 문학철 포트폴리오 |
| 유형 | 개인 포트폴리오 웹사이트 (신입 취준용) |
| 형태 | 반응형 웹 (원페이지 스크롤 + 프로젝트 상세 페이지) |
| 기간 | 약 3~4주 (문서 → 세팅 → 구현 → 배포) |

## 2. 목적 (Why)

- 채용 담당자가 **짧은 시간(약 5분)** 안에 지원자의 실력과 성향을 파악하게 한다.
- 이력서/GitHub만으로 전달되지 않는 **프로젝트의 맥락과 문제 해결 과정**을 보여준다.
- "직접 만든 사이트"라는 것 자체가 프론트엔드 역량의 증거가 되게 한다.

### 성공 기준 (measurable)

- [ ] 모바일/데스크톱 모두에서 레이아웃 깨짐 없음
- [ ] Lighthouse 성능·접근성 90점 이상
- [ ] 첫 화면 로딩 2초 이내 (배포 환경)
- [ ] 이력서·GitHub·이메일로 이어지는 CTA가 모든 화면에서 도달 가능

## 3. 타깃 사용자 (Who)

| 우선순위 | 대상 | 니즈 |
| --- | --- | --- |
| 1순위 | 채용 담당자 / 팀 리더 | "이 사람이 우리 팀에서 일할 수 있는가?"를 빠르게 판단 |
| 2순위 | 함께 일할 개발자 | 코드 품질, 기술적 깊이 확인 (GitHub 링크) |
| 3순위 | 지인 / 네트워킹 | 근황 및 대표작 공유 |

## 4. 핵심 메시지 (What)

> "꾸준히 만들고, 문제를 끝까지 해결하는 신입 개발자"

- 화려함보다 **완성도와 명료함**을 우선한다.
- 모든 프로젝트는 "무엇을, 왜, 어떻게, 결과는" 4요소로 설명한다.

---

## 5. 정보구조 (IA)

### 5.1 사이트맵

```
/                       (메인 — 원페이지 스크롤)
├─ #home                Hero / 첫인상
├─ #about               자기소개 / 사진 / 한 줄 소개
├─ #skills              기술 스택
├─ #projects            프로젝트 목록 (카드 그리드)
├─ #experience          경력 / 활동 / 교육 (타임라인)
└─ #contact             연락처 / CTA

/projects/:id           (프로젝트 상세 페이지 — 선택)
```

> 원페이지로 시작하고, 프로젝트가 많아지면 `/projects/:id` 상세 페이지를 추가하는 확장 구조.

### 5.2 글로벌 네비게이션

- 고정(sticky) 헤더: 로고(이름) + 섹션 앵커 링크 + 이력서 다운로드 버튼
- 모바일: 햄버거 메뉴
- 스크롤 시 현재 섹션 하이라이트(active)

## 6. 섹션별 콘텐츠 정의

### 6.1 Hero (#home)
- 이름 / 직무 한 줄 (예: "웹 프론트엔드 개발자를 준비하는 문학철입니다")
- 핵심 태그라인 1문장
- 주요 CTA 2개: `프로젝트 보기`, `이력서 다운로드`
- 소셜 아이콘: GitHub, 이메일, (선택) 블로그

### 6.2 About (#about)
- 프로필 사진 (선택)
- 3~5문장 자기소개: 어떤 개발자인지, 강점, 관심 분야
- 간단한 정보 리스트: 지역, 학력, 관심 기술

### 6.3 Skills (#skills)
- 카테고리별 정리: `Frontend` / `Language` / `Tools` / `Etc`
- 아이콘 + 이름 나열 (숙련도 막대는 신뢰도 논란이 있어 지양 권장)
- 예: React, JavaScript, HTML/CSS, Git, Figma

### 6.4 Projects (#projects) — 가장 중요
카드 그리드로 표시. 카드당 정보:
- 썸네일 이미지
- 프로젝트명 / 한 줄 요약
- 사용 기술 태그
- 링크: `Live Demo`, `GitHub`

상세(모달 또는 상세 페이지)에는 **STAR 구조** 권장:
| 항목 | 내용 |
| --- | --- |
| 개요 | 무엇을 만들었나 (1~2문장) |
| 기간/인원 | 예: 2주 / 개인 |
| 역할 | 내가 맡은 부분 |
| 문제와 해결 | 겪은 문제 → 어떻게 해결했나 (핵심!) |
| 배운 점 | 회고 |

> 프로젝트는 **개수보다 깊이**. 잘 설명한 3개 > 얕은 8개.

### 6.5 Experience (#experience)
- 타임라인 형태
- 교육(부트캠프/전공), 대외활동, 인턴/알바 중 개발 관련 항목
- 각 항목: 기간, 기관/활동명, 한 줄 설명

### 6.6 Contact (#contact)
- 이메일 (클릭 시 mailto 또는 복사 버튼)
- GitHub / 블로그 / (선택) LinkedIn
- (선택) 간단한 문의 폼 — Formspree 등 무료 서비스 활용
- 푸터: © 연도 이름

## 7. 콘텐츠 준비 체크리스트

문서보다 먼저 **내용(데이터)** 이 있어야 개발이 빨라집니다.

- [ ] 한 줄 소개 / 태그라인 확정
- [ ] 자기소개 문단 작성
- [ ] 프로젝트 3개 이상 정리 (위 STAR 표 채우기)
- [ ] 프로젝트 썸네일/스크린샷 이미지 준비
- [ ] 이력서 PDF 준비 (다운로드용)
- [ ] GitHub / 이메일 / 블로그 링크 확정
- [ ] 프로필 사진 (선택)

## 8. 범위 밖 (Out of Scope)

- 로그인/회원 기능 없음
- 관리자(CMS) 없음 — 콘텐츠는 코드 내 데이터 파일로 관리
- 다국어(i18n)는 v2 이후 고려
